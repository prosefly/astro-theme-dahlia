title: Theme Tokens
description: Reference the CSS tokens exposed by Dahlia and Prosefly components.

Dahlia exposes CSS tokens for theme colors, typography, shape, layout, prose, and
the Prosefly component bridge. Use these tokens when a project needs deeper
styling control than `appearance` provides.

## Gray Scale

`appearance.gray` maps one neutral palette into the shared `--dahlia-gray-*`
scale.

| Token | Purpose |
| --- | --- |
| `--dahlia-gray-50` ... `--dahlia-gray-950` | Active neutral scale for the current gray setting. |

Supported gray settings are `slate`, `zinc`, `neutral`, and `stone`.

## Semantic Colors

These are the main tokens components should use.

| Token | Purpose |
| --- | --- |
| `--dahlia-background` | Page and shell background. |
| `--dahlia-surface` | Subtle panels, hover backgrounds, and neutral soft UI. |
| `--dahlia-text-strong` | Headings, labels, active text, and high-emphasis UI. |
| `--dahlia-text` | Body copy and default foreground. |
| `--dahlia-text-muted` | Secondary text, inactive navigation, captions, and helper copy. |
| `--dahlia-border-muted` | Default component borders. |
| `--dahlia-border-subtle` | Low-emphasis dividers and sticky chrome borders. |
| `--dahlia-border-hover` | Stronger border state for hoverable controls. |
| `--dahlia-code-background` | Inline code and compact code preview background. |
| `--dahlia-code-border` | Plain code block border. |

Light mode derives text from darker gray steps. Dark mode switches these tokens
to lighter gray steps and darker surfaces.

## Accent Colors

| Token | Purpose |
| --- | --- |
| `--dahlia-accent-light` | Accent value used in light mode. |
| `--dahlia-accent-dark` | Accent value used in dark mode. |
| `--dahlia-accent` | Active accent for the current mode. |
| `--dahlia-accent-soft` | Low-emphasis active and hover background. |
| `--dahlia-accent-contrast` | Text on solid accent backgrounds. |

Built-in accents use Tailwind `600` in light mode and `400` in dark mode.
Custom hex accents are converted to light and dark OKLCH values.

## Radius

| Token | Purpose |
| --- | --- |
| `--dahlia-radius-sm` | Inline code, small focus targets, and compact controls. |
| `--dahlia-radius-md` | Buttons, nav items, sidebar items, and form-like controls. |
| `--dahlia-radius-lg` | Cards, callouts, dropdowns, and larger surfaces. |
| `--dahlia-radius-full` | Badges, circular buttons, and round markers. |

`data-radius` controls these values. Supported settings are `none`, `small`,
`medium`, `large`, and `full`.

## Typography

| Token | Purpose |
| --- | --- |
| `--dahlia-system-sans` | Built-in system sans fallback stack. |
| `--dahlia-system-mono` | Built-in system mono fallback stack. |
| `--dahlia-font-sans` | Active sans font stack. |
| `--dahlia-font-mono` | Active mono font stack. |
| `--default-font-family` | Tailwind default font family bridge. |
| `--default-mono-font-family` | Tailwind default mono font family bridge. |
| `--default-font-feature-settings` | Default sans feature settings. |
| `--default-mono-font-feature-settings` | Default mono feature settings. |

Dahlia does not load web fonts by default. Override `--dahlia-font-sans` and
`--dahlia-font-mono` after loading project fonts.

```css
:root {
  --dahlia-font-sans: "Inter", var(--dahlia-system-sans);
  --dahlia-font-mono: "JetBrains Mono", var(--dahlia-system-mono);
}
```

## Component-Local Tokens

Some MDX components define local tokens for their internal layout.

| Token | Owner | Purpose |
| --- | --- | --- |
| `--pf-steps-start` | `Steps` | Counter start offset. |
| `--pf-steps-bullet-size` | `Steps` | Marker size. |
| `--pf-steps-bullet-margin` | `Steps` | Gap below each marker before the connector line. |
| `--pf-steps-line` | `Steps` | Connector line color. |
| `--pf-steps-marker-background` | `Steps` | Marker background. |
| `--pf-steps-marker-foreground` | `Steps` | Marker text color. |
| `--pf-badge-radius` | `Badge` | Badge corner radius. |
| `--pf-file-tree-border` | `FileTree` | File tree outer border color. |
| `--pf-file-tree-line` | `FileTree` | Nested guide line color. |

Component-local tokens are implementation details. Prefer the semantic tokens
above unless a component explicitly documents an override.

## Overriding Tokens

Override tokens in project CSS when `appearance` is not enough.

```css
:root {
  --dahlia-background: oklch(0.99 0.01 260);
  --dahlia-text: oklch(0.32 0.03 260);
  --dahlia-surface: oklch(0.96 0.015 260);
  --dahlia-border-muted: color-mix(in oklab, var(--dahlia-text-muted) 24%, transparent);
}
```

Update related tokens together. Background, surface, text, muted text, borders,
and code colors should be treated as a set.
