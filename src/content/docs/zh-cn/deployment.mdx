Dahlia 生成静态 Astro 站点。部署时需要设置构建命令、`dist/` 输出目录和
正确的公开站点 URL。

## 验证生产构建

<Steps>

1. **运行项目检查。**

   ```sh
   pnpm check
   ```

2. **构建站点。**

   ```sh
   pnpm build
   ```

3. **预览生成结果。**

   ```sh
   pnpm preview
   ```

   打开几篇文档，搜索一个页面标题；如果启用了 i18n，切换语言；同时检查
   previous/next links 是否正确。

</Steps>

<Callout type="warning" title="构建可能需要网络访问">
  Iconify icons 和远程 embed metadata 可能会在构建时解析。请确保 CI 能访问
  对应服务，或者配置内部 Iconify endpoint 并为 embed 提供明确 metadata。
</Callout>

## 托管平台设置

Vercel、Netlify、Cloudflare Pages 和其他静态托管平台可以使用相同配置：

| 设置 | 值 |
| --- | --- |
| Install command | `pnpm install --frozen-lockfile` |
| Build command | `pnpm build` |
| Publish directory | `dist` |

在 Astro 配置中设置生产域名，确保 canonical URL、metadata 和生成链接正确：

```ts title="astro.config.ts"
import { defineConfig } from 'astro/config';
import dahlia from '@prosefly/astro-theme-dahlia';

export default defineConfig({
  site: 'https://docs.example.com',
  integrations: [dahlia()],
});
```

如果整个站点部署在 `https://example.com/product/` 这样的子路径下，还要设置
Astro 的 `base`。`docsBase` 含义不同：它把文档放到 Astro 站点内部的某个路由，
例如 `/docs`。

## 部署后检查

- 直接打开 docs index 和一篇嵌套文档，不要只通过客户端导航访问。
- 确认当前 locale 的 `search.json` 返回 `200`。
- 启用 `view-markdown` 时，打开一条生成的 `.md` 路由。
- 检查 source/edit links 是否指向配置的仓库和 branch。
- 确认托管平台能返回生成的 `404.html` 页面。
